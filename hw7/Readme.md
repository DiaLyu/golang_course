# Домашнее задание №7 - gRPC Микросервис

## Цель задания

Задание направлено на изучение:

* Работа с протоколом **gRPC** и **Protocol Buffers (proto3)**
* Реализация **Streaming RPC** (потоковая передача данных)
* Механизмы авторизации через **gRPC Interceptors**
* Конкурентное программирование в Go (Mutex, Channels, WaitGroup)
* Управление жизненным циклом сервиса через **Context**
* Отсутствие глобальных переменных (инкапсуляция в замыкании)

## Архитектура

### 1. Инициализация (StartMyMicroservice)

При старте:

* Парсится JSON-строка с правами доступа (ACL).
* Формируется внутренняя `map[string]map[string]bool` для проверки прав за $O(1)$.
* Создается экземпляр сервера с внутренними слайсами каналов для рассылки событий.
* Регистрируются обработчики `Admin` и `Biz` сервисов.

### 2. Механизм контроля доступа (ACL)

Проверка прав реализована в интерцепторах:

* Из `IncomingContext` извлекается имя `consumer`.
* Метод сверяется со списком разрешенных (поддерживаются полные пути и маски с `*`).
* При отсутствии прав возвращается ошибка `codes.Unauthenticated`.

### 3. Система логирования (Fan-out)

Реализована через паттерн Pub/Sub:

* При вызове `Admin.Logging` создается канал и регистрируется в сервере.
* Каждый вызов любого метода через интерцептор инициирует рассылку `Event` по всем активным каналам логгеров.
* Безопасность обеспечена через `sync.Mutex`.

### 4. Сбор и агрегация статистики

Особенности реализации:

* Статистика собирается асинхронно через события в интерцепторах.
* В методе `Admin.Statistics` используются локальные счетчики (`map`) внутри горутины стрима.
* Это гарантирует, что каждый клиент получает данные только за свой интервал времени, и обнуление данных одного клиента не влияет на другого.

### 5. Graceful Shutdown

* Сервер запускается в отдельной горутине.
* Основной поток ожидает сигнала `<-ctx.Done()`.
* Вызывается `grpcServer.Stop()` и `listener.Close()`, что гарантирует завершение всех активных соединений и отсутствие утечек горутин.
